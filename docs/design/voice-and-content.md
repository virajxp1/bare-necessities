# Voice and Content

This document defines how the site should sound and how content should be framed.

## Voice

The voice should be:

- direct
- clear
- grounded
- quietly confident

It should avoid:

- exaggerated self-promotion
- startup cliché language
- vague statements about passion or innovation
- filler copy written only to occupy space

## Core Messaging

The site should consistently reinforce a small set of ideas:

- simplicity is a competitive advantage
- useful software beats impressive complexity
- judgment matters as much as implementation
- writing is part of the work, not separate from it

## Writing Style

### Headlines

- short
- decisive
- specific

Good characteristics:

- they sound like a point of view
- they avoid buzzwords
- they can stand alone without extra explanation

### Supporting Copy

- explain value in plain language
- favor concrete nouns and verbs
- keep paragraphs short

### Project Descriptions

Each project should answer:

- what it is
- why it exists
- what made it worth building

Avoid turning project summaries into raw stack lists.

### About Copy

The About page should answer:

- who you are
- how you work
- what kinds of problems you care about

It should not read like a LinkedIn profile pasted into a website.

## Tone by Section

### Home

- concise
- assertive
- inviting

### Work

- factual
- outcome-oriented
- selective

### Blog

- thoughtful
- opinionated when warranted
- readable without performance

### About

- personal, but edited
- warm, but not casual to the point of vagueness

## CTA Language

Use straightforward action labels:

- `View work`
- `Read the blog`
- `All posts`
- `More about me`

Avoid over-written CTA copy such as:

- `Let’s build something amazing`
- `Discover my journey`
- `Explore my world`

## Content Constraints

- Each homepage section should justify its presence quickly
- Prefer fewer, stronger projects over exhaustive listings
- Prefer fewer, better posts in a preview section
- If a piece of text repeats what the heading already says, cut it

## Editorial Markers

Use editorial labels and metadata carefully:

- categories should help orientation, not act as decoration
- dates and read times should be easy to find but visually quiet
- section labels should be sparse and consistent

## Sample Messaging Direction

These are directional examples, not locked copy:

- `Software, stripped to what matters.`
- `I build useful systems with a bias toward clarity, speed, and restraint.`
- `Selected work on tools, systems, and software that solves real problems.`
- `Writing on building, simplification, and engineering judgment.`

## Editing Standard

Before shipping copy, check:

1. Is it specific?
2. Is it necessary?
3. Does it sound like a person with judgment?
4. Could a reader understand it in one pass?

If not, simplify it.
