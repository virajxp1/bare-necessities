# Design Principles

This document captures the non-negotiable principles behind the site.

## Purpose

The site exists to do three things clearly:

- show selected projects
- publish writing and ideas
- explain who the person behind the work is

It should not feel like a startup landing page, a resume dump, or a template-heavy portfolio.

## Audience

The design should work for three overlapping readers:

- potential clients looking for taste and competence
- hiring teams evaluating judgment and communication
- technical peers interested in projects, tools, and writing

## Brand Character

The site should feel:

- precise
- restrained
- thoughtful

Secondary traits:

- quietly opinionated
- editorial
- pragmatic

## Core Positioning

The site should communicate one central idea:

> Good software comes from clarity, reduction, and strong judgment.

The portfolio should not simply claim this. The layout, copy, and interactions should demonstrate it.

## Design Rules

### 1. Simplicity should feel intentional

Minimalism is only useful when it sharpens meaning. Empty space, sparse color, and restrained UI should create clarity, not absence.

### 2. Editorial over app-like

The site should borrow from publishing and studio websites more than SaaS marketing pages:

- stronger typography
- fewer containers
- cleaner horizontal rules
- more emphasis on sequence and reading flow

### 3. Make hierarchy obvious

Every page should clearly answer:

- what this page is about
- what matters most
- where to go next

If multiple elements compete equally, the hierarchy is wrong.

### 4. Restraint creates emphasis

Accent colors, pills, borders, and tags should appear only when they help orientation or emphasis. Repetition reduces impact.

### 5. Projects lead, personality follows

The site is personal, but not diaristic. Work should stay central. The About section should support credibility and context, not become the main event.

### 6. Writing should feel like part of the product

The blog is not an afterthought. It should look structurally integrated with the rest of the site and reinforce the same point of view.

## Anti-Patterns

Avoid these patterns even if they are easy to implement:

- oversized metric blocks
- testimonial carousels
- glass cards and decorative blur
- multi-color gradients
- generic developer hero copy
- endless equal-sized feature cards
- icons used only to fill space
- resume-style timeline as the main about structure

## Decision Filter

When a design choice is unclear, use this filter:

1. Does it improve clarity?
2. Does it strengthen the editorial tone?
3. Does it avoid looking like a generic developer template?
4. Does it help the reader understand work, writing, or the person behind them?

If the answer is no to two or more of those questions, the choice should probably be removed.
