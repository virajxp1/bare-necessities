## Design Context

Synthesized from `docs/design/` (color-palette, design-principles, typography,
layout-and-spacing, components, page-blueprints, voice-and-content) and from
conversations with the site's owner, Viraj Parikh.

### Users

Three overlapping readers, all finding the site via direct link or search:

- **Potential clients / collaborators** evaluating taste and competence before
  reaching out.
- **Hiring managers and engineering leaders** looking for judgment and
  communication ability, not just a resume.
- **Technical peers** curious about specific projects, tooling, or essays.

Viewing context: desktop-primary (reading on a laptop during work hours), with
meaningful mobile traffic. The reader is usually skimming with intent — they
want to form an impression fast, then decide whether to go deeper.

### Brand Personality

**Three words**: precise, restrained, thoughtful.

**Secondary traits**: quietly opinionated, editorial, pragmatic.

**Voice** (per `voice-and-content.md`): direct, clear, grounded, quietly
confident. Avoid exaggerated self-promotion, startup clichés, and filler copy.

**Emotional goal**: the reader should come away thinking *"this person has
judgment and taste"* — not *"this person ships a lot of features"*.

### Aesthetic Direction

**Category**: editorial / literary studio site, NOT SaaS landing page, NOT
developer-template portfolio.

**Theme**: light, warm. A Papaya Whip (`#FDF0D5`) canvas with deep plum ink.
Dark mode is NOT in scope.

**Reference mood**: independent magazine, hand-set letterpress book, Bauhaus
publishing, a well-made studio site. Editorial pacing over app-like density.

**Anti-references** (from `design-principles.md` and lived experience in this
codebase):

- Oversized metric blocks, testimonial carousels
- Glass cards, decorative blur, halos, glowing auras
- Multi-color gradients (especially gradient text — explicitly banned)
- Endless equal-size feature cards
- Resume-style timeline as the primary About structure
- Icons used only to fill space
- Generic developer hero copy ("I build things for the web")
- The Instrument Sans / DM Sans / Space Grotesk / Fraunces default look

**Palette** (LOCKED — do not introduce additional hues, per `color-palette.md`):

| Token                | Hex       | Role                                 |
| -------------------- | --------- | ------------------------------------ |
| Papaya Whip          | `#FDF0D5` | Primary canvas                       |
| Midnight Violet      | `#331832` | Ink, headings, structural UI         |
| Cinnabar             | `#F0544F` | Primary highlight / CTA accent       |
| Raspberry Red        | `#D81E5B` | Editorial labels, active/focus       |
| Ash Grey             | `#C6D8D3` | Supporting surface, section bands    |

Distribution: ~70% Papaya Whip, ~20% Midnight Violet ink, ~8% Cinnabar,
~2% Raspberry Red. Ash Grey as a wide supporting band, not a card fill
default.

**Typography** (LOCKED by `typography.md`, even though these fonts overlap
with impeccable's reflex-reject list):

- **Display**: Cabinet Grotesk (700/800) — hero, page headers, project titles
- **Body**: Instrument Sans — body, nav, UI, supporting copy

If revisiting font choices, the replacement must still feel editorial and
assertive, NOT tech-bro geometric or startup-soft.

### Design Principles

1. **Editorial over app-like.** Borrow from publishing: strong typography,
   horizontal rules, reading flow. No equal-sized feature cards, no SaaS
   hero stacks.
2. **Restraint creates emphasis.** One accent moment per viewport beats many
   competing accents. Cinnabar is powerful because it's rare.
3. **Hierarchy must be obvious.** Every page answers "what is this, what
   matters most, where to go next." If elements compete equally, the
   hierarchy is wrong.
4. **Projects lead, personality follows.** About supports credibility; it
   doesn't become the main event. Work is the proof.
5. **Simplicity should feel intentional.** Whitespace and sparse color should
   read as precision, not absence. Fewer, stronger components over variant
   explosion.

### Implementation Notes

- Tailwind v4, Next.js 16 App Router, React 19
- Content lives in `content/posts/*.md`, `content/projects/*.md`,
  `content/timeline/*.md` with YAML frontmatter; loader in `content/lib.ts`
- CSS tokens are centralized in `app/globals.css`. Component styles should
  reference semantic tokens (`--color-ink`, `--color-accent`), never raw hex.
- Footer uses Midnight Violet base with Papaya Whip text (per component spec).
